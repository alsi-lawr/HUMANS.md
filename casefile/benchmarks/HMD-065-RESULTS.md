## Contract and implementation

- `Store::read_editable_entry(path, kind)` normalizes the existing portable path grammar, resolves the deepest activated owner, guarded-reads only the requested writable ticket/epic/board and activation, and returns its original bytes/metadata revision. Missing supported target is `None`; malformed/unsafe/wrong-kind targets are explicit ordinary failures. It reuses `selected_entry`/`classify_facts`. Canonical cross-record validation still happens independently in preview/apply, not in a new editor validator.
- `Store::project_writer_binding(investigation, strategy_id)` reads exactly the implementation matrix and optional binding plus activation. Shared parsed facts and `resolve_binding` preserve the existing serialized `WriterBindingProjection` fields and absent/unresolved/resolved/invalid states. It neither reparses retained content nor derives unrelated records. Adapter/writer-count diagnostics never rewrote scan classification: valid-schema mismatches remain **unresolved**, not invalid. No unused duplicate diagnostics pass is run. `require_writer_progress` remains the separate validated canonical progress/ticket spawn gate; projection does not newly require or grant permission.
- Private selected observations verify requested descriptors and necessary activation/owner/prefix facts, without whole-store inventory/hash or new public freshness tokens. One ScopeIndex is used for initial target selection; verification re-resolves owners only if activation metadata changed. Existing regular-file/no-follow/containment checks remain.
- Editor review refuses a preview whose expected target revision differs from the entry acquired **before** the editor ran. External edits win; the unreviewed draft is retained. Later Store apply still performs its own fresh admission. Unchanged editor exit discards its draft without mutation. Successful apply uses the committed `ApplyResult` path/revision, not a direct post-apply full scan; the existing TUI resumption/load remains unchanged.
- MCP reads LF-delimited frames with the cap checked **before** extending the frame. Oversize or EOF with a partial frame closes the session without unbounded draining/recovery or a new timeout. Complete encoded outer envelopes, including newline, are bounded before emission. Oversize result gets a concise JSON-RPC internal error with the unchanged actual request ID; if that ID cannot fit the error, the session fails without partial/truncated output. Actual stdout I/O errors remain ordinary failures. Existing dated MCP versions, Provider5 ID-only approval and structured rollback channels remain unchanged.
